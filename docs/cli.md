# `@lorekit/cli` — command reference

The full role/behaviour description for the `@lorekit/cli` package (`packages/cli/`), extracted from the root [`CLAUDE.md`](../CLAUDE.md) Package map. The CLAUDE.md row keeps a terse command list and links here.

## Command surface

Zero-dep Node CLI: `install` (scaffolds the `lorekit-memory` + `lorekit-setup` + `lorekit-groom` skills, MCP server, and the deterministic lifecycle hooks into `.claude`/`~/.claude` per a project/global prompt — the plugin's three parts without a marketplace. **The hooks are an explicit choice, not a silent side effect**: a second prompt offers `all` (`SessionStart`, `UserPromptSubmit`, `PostToolUseFailure`, `Stop`) / `read-only` (`SessionStart` only) / `none` (`HOOK_MODES`/`hookEventsForMode`/`hookModeFromEvents` in `config.mjs`), preselected to the DETECTED state via `installedHookEvents` — the same reader `doctor` uses — so a fresh install preselects `all` while a re-run never resurrects hooks the user declined. `--hooks <mode>` selects non-interactively and bypasses the already-installed short-circuit; `--hooks none` REMOVES wired hooks whereas the older `--no-hooks` stays skip-only. `upsertClaudeHooks` takes the event list and PRUNES lorekit entries for events outside it, so `all → read-only` is a real downgrade. It is also CONVERGENT — an event carrying SEVERAL lorekit entries keeps exactly ONE (the first updated in place, every further one deleted and reported as `deduped`), because reconciling only the first left a duplicated `settings.json` firing the hook twice forever and made `install --force` unable to repair the state it is most often run against. `LOREKIT_HOOK_RE` decides what counts as ours, so it tolerates a leading path/quote, a pinned `@lorekit/cli@x.y.z` and a `.cmd`/`.exe` suffix (a form it MISSES is appended alongside, which is how the duplicates were born) while requiring a leading boundary so an unrelated `mylorekit hook …` is never claimed. `install` returns the `{ exitCode, ... }` shape carrying a bounded `lorekit.cli.hooks_mode`; an INTERACTIVE `--force` prompts keep/replace/remove for an already-configured token instead of silently reusing it — the pure `tokenPlan` decides, and a non-interactive run still reuses), `doctor` (connectivity/token/scope health checks; `connectivity` probes the PUBLIC `/health` function and therefore proves only the network path, so a separate `authentication` check calls `RemoteStore.verifyAuth()` — one authenticated `GET /memories?limit=1` — and FAILS on a 401 revoked/deleted token, PASSES a 403 as accepted-but-unpermitted [a healthy `lk_wo_*`], and never turns a 429/5xx/network error into a revoked verdict), `list` (alias `ls` — read-only human view of the lessons for the cwd's scopes, project/branch/repo/global, split into an **Offline** local-store section and a **Remote** hosted section that degrades gracefully when unconfigured; `--json`/`--scope`; `--all` drains all pages via `gatherStream` [default is single-page `gather()`]; `--max <n>` hard-caps entries surveyed [default 5000]; `--since`/`--until <iso-date>` forward `created_since`/`created_until` to the REST request; independently builds BOTH stores via `src/stores.mjs` + renders via the reusable `src/lessons-view.mjs`, the seam all the `search`/`show`/`stats`/`diff` read commands stack on; the shared deny-wins block those five read commands all use is extracted into `resolveDenies(root,{env})` in `control.mjs`), `search` (alias `grep` — full-text search the same scopes/stores/split as `list`; matches a **literal, case-insensitive** substring against a lesson's key OR value, via the pure `matchesQuery` (in the dependency-free `lessons-pure.mjs`, re-exported by `lessons-view.mjs`)/`filterGroups` helpers over the shared `gather()` output — NOT each store's native `search` method, whose semantics diverge (local literal-substring vs remote server-FTS); regex metachars are matched verbatim, never compiled; `--json`/`--scope`), `show` (inspect ONE lesson in full via each store's real `read({scope,key})` — complete untruncated value, scope, key, updated, tags, and which store(s) hold it; when the same `scope::key` is in both stores it shows both and flags any divergence via the pure `recordsDiverge`; exits non-zero when found in no readable store; `--json`), `stats` (at-a-glance counts of the applicable lessons **per scope** and **per store**, with per-store + grand totals, in the same Offline/Remote split; **remote counts come from `GET /memories/scopes` via `RemoteStore.listScopes()`** — the same Postgres aggregate `scopes` uses — NOT from row-draining `memory.list`, so the count is exact for any scope size; Offline tallies via pure `tallyGroups` over `gather()`; `--json`/`--scope`), `scopes` (a **store-wide** inventory — UNLIKE every other read command, NOT cwd-scoped: enumerates EVERY distinct scope present in the store with a per-scope non-archived count, so a user sees all scopes they have lessons in anywhere; pure `scopeTypeOf`/`sortScopeInventory`/`filterScopeInventory`/`summarizeScopeInventory` in `lessons-view.mjs`, sorted by scope type then name; `--json`/`--scope` [a **substring filter** over the inventory, not a single-scope selector]. **Offline enumeration is exact** — a new `LocalStore._walkEntries()`/`listScopes()` (+ `TwoTierStore.listScopes()` deduping by `scope::key` across tiers, project shadowing home) recursively walks the store and reads each file's frontmatter `scope` string, NEVER reverse-mapping the on-disk layout [which is lossy for `project::{name}`, stored by basename only], so scopes are reconstructed verbatim. **Remote enumeration is exact too** — `RemoteStore.listScopes()` calls `GET /memories/scopes`, which aggregates one `{scope,count}` row per scope in Postgres [`lorekit_memory_scopes`, migration 00039], so the Remote section renders a REAL inventory through the same `filterScopeInventory`/`summarizeScopeInventory` helpers as Offline; a denied/unconfigured/unreachable/erroring remote degrades to a short, accurate note via the shared `describeError` at exit 0 [the old `REMOTE_SCOPES_UNSUPPORTED` sentinel is gone — the surface supports enumeration now]), `diff` (compare offline vs remote for the applicable scopes and report **local-only** / **remote-only** / **conflicting** keys grouped by scope, via the pure `diffGroups` set-diff reusing `recordsDiverge`; needs BOTH stores readable — an unconfigured/denied store yields a clear `comparable:false` note at exit 0, never a crash; `--json`/`--scope`), `tree` (alias `resolve` — the scope **precedence hierarchy**: resolves the hook-injected `readOrder` scopes [project→branch→repo→global, most-specific first] and marks per key which scope's lesson **wins** and which are **shadowed**, mirroring `core/lessons.mjs`'s first-seen-wins merge EXACTLY via the SAME shared pure `resolvePrecedence` [now in the dependency-free `lessons-pure.mjs`, re-exported by `lessons-view.mjs`]; per-store; `--json`/`--scope`), `lint` (flag low-quality lessons across the applicable scopes/stores — pure `LINT_RULES`/`lintEntry`/`lintGroups`: **empty-value**/**short-value**/**untrimmed-value**/**empty-key**/**volatile-key** [a per-sighting identifier in the key — a 6+ digit run or a segment-anchored `pr<n>`/`issue<n>` — which never collides, so the upsert never dedups and `seen_count` stays frozen at 1; conservative by design so `oauth2`/`sha256`/`wcag22`/semver never fire, with an embedder-only `{ volatileKeyAllow }` opts hatch mirroring `short-value`'s `minValueLen`, no config key]/**malformed-scope** [via the canonical `scopeIssue` validator], each rule independently tested; **exits non-zero when any finding exists** so it's a CI gate; `--json`/`--scope`), `dedupe` (heuristic near-duplicate detection — pure `tokenize`/`similarity` [zero-dep **Jaccard word-token overlap**, NOT embeddings]/`clusterDuplicatesBlocked` [inverted-index token-blocking, O(candidate_pairs) not O(n²), produces identical clusters to the oracle `clusterDuplicates` when Jaccard ≥ threshold > 0]; population is capped at 2000 entries for memory safety — when the cap is hit, a narrowing warning is printed; `--key-prefix` and `--since` narrow the population; per-store across scopes; `--json`/`--scope`/`--threshold` [default 0.8]), `link` (alias `url` — print a shareable dashboard **deep-link URL** to stdout, nothing else, so it pipes into a clipboard/PR/Slack: no-arg → the cwd's most-specific scope, `<scope>` → the scope-filtered Explorer, `<scope> <key>` / `<scope::key>` → a lesson detail-sheet link setting BOTH `?lesson=` and `?scope=`, with `--key` naming a key that itself contains `::` (the same escape hatch `show`/`write` have); filter flags mirror the Explorer [`--q`/`--owner`/`--range`|`--from`|`--to`/`--archived`/`--view`], `--base`/`LOREKIT_APP_URL` override the host [default `https://lorekit.io`], `--json` → `{ url, surface, base, params }`. The read commands `show`/`search`/`list`/`tree` also take a `--link` flag that short-circuits to the equivalent URL for the current invocation. All URLs are built by the dependency-free **`src/deeplink-pure.mjs`** [the `lessons-pure.mjs` zero-import precedent], which encodes every param `encodeURIComponent(JSON.stringify(value))` and omits any param equal to its `useUrlState` default — the exact inverse of the web app's read [`packages/web/src/lib/hooks/useUrlState.ts`], mirroring `ScopeHealthCard.tsx`. `core/lessons.mjs`'s `writeConfirmation` [the hook link] now delegates to that module, **fixing a real bug**: it previously raw-encoded `?scope=<scope>`, which the dashboard's `JSON.parse` rejected into an all-scopes fallback; write-confirmations now deep-link to the exact lesson), `hook` (the shared hook engine behind the plugins — injects lessons on SessionStart, **a per-turn relevance pull on UserPromptSubmit** [`promptQuery` distils terms from the prompt → `promptLessonsFromStore` ranks the store's hits and injects at most three the session has not already been shown, tracked by `core/state.mjs`'s append-only shown-set; gated by `hooks.userPrompt` (`on` default | `off`) and run under `PROMPT_FETCH_TIMEOUT_MS` rather than `restFetch`'s 10s default, because it sits on the user's critical path], **relevant lessons + a write-nudge on a tool failure** [`failureQuery` → `relevantLessonsFromStore` QUERIES the store — ONE `store.search` carrying all terms (OR) across the scope hierarchy, deduped/capped by the pure `dedupeRelevant` — not a post-filter of the injected set], and a **friction-gated** retrospective nudge on Stop [`hooks.stop`: `friction` default | `always` | `off`; `core/friction.mjs`'s `detectFriction`/`shouldRetrospect` read the transcript and stay silent on a clean session]; always exit 0, best-effort, never blocks the host), and `mcp` (a hand-rolled local stdio MCP server exposing `memory.*` from the resolved store — lets `.mcp.json` point at the CLI instead of `mcp-remote`, for offline local-mode tool calls). Ships three skills under `skill/*` — `lorekit-memory` (runtime read/write), `lorekit-setup` (authoring a self-improvement loop into a host), and `lorekit-groom` (a propose-then-confirm grooming pass over an accumulated store: survey→lint→dedupe/merge→expiry→prune, analysis via the CLI read commands and mutation via the `memory.*` MCP tools since there is no `lorekit delete`); `install`/`uninstall`/`doctor` iterate the `SKILLS` list in `config.mjs`, and `scripts/sync-plugin-skill.mjs` mirrors every `skill/*` into the plugin. Human-facing commands (`install`/`uninstall`/`doctor`/`list`/`search`/`show`/`stats`/`scopes`/`diff`/`tree`/`lint`/`dedupe`/`link`/`migrate`) emit one OTel span + counter point per run via a zero-dep self-contained OTLP/JSON `fetch` exporter (`src/telemetry.mjs`, the `_shared/otel.ts` pattern) — `service.name=cli`, `service.namespace=lorekit`, no-PII attrs, opt-out via `LOREKIT_TELEMETRY`/`DO_NOT_TRACK`; `hook`/`mcp` stay uninstrumented. The ingesting-only Dash0 token is never committed — `src/telemetry-token.mjs` is empty in git and injected at publish time from the `LOREKIT_TELEMETRY_TOKEN` secret by `scripts/inject-telemetry-token.mjs` (wired into `release.yml`'s `publish-cli` job); `LOREKIT_TELEMETRY_TOKEN`/`OTEL_EXPORTER_OTLP_HEADERS` env override it at runtime. Verified by its own `node:test` suite; excluded from the NX TS lint gate.
